My Philosophy

How I Think About Documentation

  • Documentation is a product, not a deliverable
  • Good documentation reduces support tickets, great documentation prevents them
  • Onboarding should take less than 10 minutes for a motivated developer
  • Every API must have a working quickstart before it ships
  • Clarity beats completeness
  • Standards (OpenAPI, Markdown) exist to help readers, not constrain writers
