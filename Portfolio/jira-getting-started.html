Getting Started with Jira

A first-day onboarding guide for new Jira users who need projects, issues, and boards to make sense quickly

Version: 2.0 Updated: March 13, 2026 Audience: New Jira users and newly onboarded team members

This guide introduces the Jira concepts new users need first: what a project is, how issues move through a workflow, and how to create your first project and issue without getting lost in the interface.

Quickstart Checklist

Use this quickstart when your goal is simple: create a project, create one issue, and move that issue through the board without getting lost in Jira settings.

Have these ready

  • Access to the correct Jira site
  • A project name or the project you need to join
  • A short summary of the first task, bug, or story you want to track

First-day Jira path

  1. Confirm whether you need to create a new project or work inside an existing one.
  2. Create one issue with a clear summary and enough context for the assignee.
  3. Open the board and move the issue to the correct workflow column so status is visible to the team.
Result: You can complete the core Jira workflow new users usually need first: project access, issue creation, and board-based status tracking.

Jira Overview

Jira is a work management platform teams use to plan, assign, track, and report on work. Product, engineering, support, and operations teams often use Jira to organize work into projects, represent that work as issues, and move issues through a visible workflow.

Centralized Work Tracking

Projects, issues, comments, and due dates stay in one system instead of being spread across chat, email, and spreadsheets.

Improved Collaboration

Teams can assign work, add context, ask follow-up questions, and see status changes without losing history.

Visual Workflows

Boards help teams see what is queued, in progress, blocked, or done so bottlenecks surface earlier.

Powerful Reporting

Dashboards, filters, and reports show issue trends, workload, and project progress over time.

Core Concepts

These are the Jira concepts most new users need to understand before they start creating work items or moving work on a board.

Project

A project is the main workspace for a team or initiative. It contains the issues, workflows, members, views, and settings related to that body of work.

Issue

An issue is a unit of work. Depending on your team configuration, it might represent a task, bug, story, request, or epic.

Board

A board shows issues moving through workflow columns such as To Do, In Progress, and Done. Boards make status visible at a glance.

Workflow

A workflow defines the statuses and transitions an issue follows from creation to completion. Teams often customize workflows to match how they operate.

Jira User Interface

The Jira interface can feel dense at first, but most onboarding tasks rely on only a few areas: global navigation, the left sidebar, and the current project view.

Top Pane

  • Switch sites or apps: Move between Atlassian products such as Confluence, Bitbucket, and Jira Service Management.
  • Create: Open the issue creation form from anywhere in Jira.
  • Search: Find issues, projects, filters, boards, and people across the site.
  • Help and Settings: Access product help, account options, and administrative settings.
  • Notifications: Review updates related to your work, mentions, and watched items.

Left Pane

  • Projects: Open a specific project and its work views.
  • Boards: Access the Kanban or Scrum board connected to a project.
  • Backlog: Prioritize work before it moves into active execution.
  • Timeline: Review work against a time-based plan.
  • Reports: Open burndown, throughput, or status reporting views depending on configuration.
  • Starred and Recent: Save time by returning to the projects and boards you use most often.
Tip: New users usually need only three actions at first: open the correct project, create an issue, and update issue status on the board.

Create a Project

Create a project when you need a dedicated workspace for a team, product area, or initiative.

Prerequisites

  • Administrative access to create projects
  • A project name, short key, and preferred template
  • Basic understanding of whether your team needs a team-managed or company-managed project

Steps to Create a Project

  1. On your browser, open the Jira website and sign in.
  2. On the home screen, in the left pane, select the plus icon next to Projects.
  3. On the Project templates screen, select a template.
  4. Select Use template.
  5. Select either team-managed or company-managed based on how much control and standardization your organization needs.
    Note: Team-managed projects are simpler for small teams. Company-managed projects are better when workflows and permissions must stay standardized across teams.
  6. On the Add project details screen, enter a clear name and project key.
  7. From the Access dropdown list, select an access level.
  8. Select Create project.
  9. On the Bring the team with you screen, enter team member names or email addresses and select their roles.
    Note: To invite teammates later, select Skip.
  10. Select Invite and continue.
Result: Jira creates the project workspace and opens the views your team will use for issue tracking and planning.

Create an Issue

Create an issue when you want to track a task, bug, story, request, or other unit of work in the project.

Prerequisites

  • Access to at least one Jira project
  • A clear summary of the work to be done

Steps to Create an Issue

  1. On your browser, open the Jira website and sign in.
  2. On the home screen, in the top pane, select Create.
  3. On the Create screen, from the Project dropdown list, select your project.
  4. From the Work type dropdown list, select Task, Bug, Story, or Epic.
  5. In the Summary field, enter a clear, action-oriented title.
  6. Set the initial Status if your team workflow allows it.
  7. (Optional) Enter the following details:
    • Description: Add context, acceptance criteria, reproduction steps, or dependencies.
    • Assignee: Select a team member.
    • Priority: Specify the priority.
    • Labels: Enter labels to categorize and group similar issues.
    • Attachments: Upload files, screenshots, or designs.
    • Linked Issues: Link this issue to related Jira work.
  8. In the Reporter field, select a reporter.
  9. Select Create.
Result: Jira adds the issue to the project and makes it available in the backlog, issue list, or board views.

Work on a Board

After issues exist, the board becomes the easiest place for most teams to track movement from planned work to completed work.

Basic board workflow

  1. Open the project and select Board in the left navigation.
  2. Find the issue you created in the appropriate column, such as To Do.
  3. Open the issue card to review description, assignee, due date, comments, and linked work.
  4. When work begins, move the issue to In Progress or the equivalent team status.
  5. Use comments and attachments to keep progress updates inside the issue instead of private chats.
  6. Move the issue to Done only when the team definition of done has been met.
Result: The board becomes a shared source of truth for current status, ownership, and next action.

Next Steps

Prioritize the backlog
