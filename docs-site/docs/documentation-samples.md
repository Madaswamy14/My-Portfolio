# Documentation Samples

This section groups the portfolio samples I migrated into the developer portal so they read like part of a cohesive documentation system instead of isolated HTML pages.

## What these case studies demonstrate

- quickstart-first structuring
- concept framing before complex tasks
- next-step guidance that extends the user journey
- portal-ready information architecture for stronger scanning and navigation

## Included samples

### [Acme Payments Developer Platform](./acme-payments/intro.md)

A developer portal case study for a fictional payments platform covering onboarding, authentication, API reference architecture, webhooks, and DevEx system design across a deeper integrated docs set.

### [Facebook Events Quickstart](./facebook-events-quickstart.md)

A workflow tutorial focused on planning, publishing, promoting, and following up on a Facebook event.

### [Jira Getting Started](./jira-getting-started.md)

A first-day onboarding guide that helps new users understand projects, issues, and boards quickly.

### [SWAPI API Reference Sample](./swapi-api-reference-sample.md)

An API reference case study that combines quickstart, conventions, endpoint detail, and troubleshooting guidance.

## Suggested review path

1. Start with the quickstart section on each page.
2. Review how the concepts section supports the task flow.
3. Compare the next-step guidance to see how each sample extends the reader journey.
